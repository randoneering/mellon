# REVIEW.md

mellon is a GitHub Action that scores new issue and pull request text and labels or closes submissions.
Many pull requests come from an automated factory worker, so the reviewer is the first check on its claims.

## Product decisions to respect

- `dist/` is generated by `npm run build`.
  Flag hand edits to `dist/`, and flag source changes to `src/` or `detector/` that ship without matching `dist/` changes.
- The classifier score is a fallible signal, not proof of AI authorship.
  Flag wording in messages or docs that presents it as proof.
- Committed workflows and runnable examples pin third-party actions to full commit SHAs.
  Consumer examples use the `REPLACE_WITH_REVIEWED_40_CHARACTER_COMMIT_SHA` placeholder on purpose; do not flag it.
- The packaged Action never installs packages or downloads models at runtime.

## What to catch

### Release and setup docs drift

Treat `README.md`, `docs/release.md`, `docs/configuration.md`, and `examples/` as operational instructions, not prose.
Check each instruction against the source of truth and flag mismatches as remediation recommended:

- Check commands against `package.json` scripts and the check list in the README `Build and test` section.
- Check generated file lists against what `scripts/build.mjs` writes.
- Check version, tag, and "first release" wording against existing release tags; `v0.1.0` and later tags already exist, so first-release steps are stale.
- Check new sections that restate an existing section for conflicting steps.

### Factory pull request claims

Factory pull request bodies start with `Written by T3 Code with Pi`.
Flag claims in the body that the diff or CI cannot support, such as checks that "passed" when the body also says tests did not run in the worker.

## Out of scope

- Do not raise style findings on `dist/`, `package-lock.json`, or `detector/package-lock.json`.
- Do not request more tests for documentation-only changes.
